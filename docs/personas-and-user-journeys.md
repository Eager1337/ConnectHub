# ConnectHub — Example Personas and User Journeys

> These are design personas created to guide prototyping. They are fictional composites, not interview participants or evidence about actual students. Validate them with research.

## Persona 1 — The busy student
**Name:** Mariama (fictional)  
**Context:** Undergraduate student balancing lectures, assignments and campus activities.  
**Needs:** Quickly see important announcements, identify event dates and avoid searching multiple channels.  
**Frustrations to validate:** Missing an update because it was shared in a group she does not follow.  
**Design implication:** Clear feed hierarchy, visible event dates and notifications.

## Persona 2 — The collaborative learner
**Name:** Ibrahim (fictional)  
**Context:** Student who prefers learning with classmates and joining course-related groups.  
**Needs:** Find peers with shared interests and discover study communities.  
**Frustrations to validate:** Not knowing which groups are active or where to ask for help.  
**Design implication:** Discover page with understandable group descriptions and membership context.

## User journey A — Save a useful post
1. Student opens Home.
2. Student scans the feed and finds a relevant study announcement.
3. Student selects Save.
4. Interface changes the control to “Saved” and displays confirmation.
5. Student opens Saved posts and finds the item.

**Success condition:** The student can save and later retrieve the post without assistance.

## User journey B — Join a campus event
1. Student opens Campus events.
2. Student reviews event date, time, location and description.
3. Student selects RSVP.
4. Interface changes the button to “Going” and confirms the action.

**Success condition:** The student can identify event details and understand whether the RSVP action was accepted by the prototype.

## User journey C — Publish a campus update
1. Student opens Home.
2. Student selects the post composer.
3. Student enters a short update.
4. Student selects Publish post.
5. The new item appears at the top of the feed.

**Success condition:** The student can publish a sample update and see it appear in the feed.
